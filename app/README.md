# app/ — 应用外壳总述

> 状态：规划中（首期骨架）

CHAINPCF（链碳台）的应用外壳层。外壳只负责"把人送进工作流、把模块接进来"，不承载任何碳核算业务逻辑。口号：数据驱动 · 绿色未来。

## 模块职责

| 职责 | 说明 |
| --- | --- |
| 启动 | 进程/会话入口，串联配置、日志、存储连接、知识库加载、模块注册 |
| 初始化 | 首次运行引导：数据目录、字典版本、因子库版本的就位检查 |
| 主窗口 / 导航 | 以核算工作流为主线的导航容器与视图路由 |
| 工作台 | 承载各模块视图的宿主区域，统一呈现状态、错误、进度、确认对话框 |
| 模块接入点 | 依据 `contracts/README.md` 的契约发现并装配模块 |

## 边界

**做什么**

- 生命周期管理：启动、初始化、退出、异常兜底重启提示。
- 视图装配：为每个模块提供挂载点、输入上下文与统一交互反馈。
- 版本呈现：向用户展示字典版本、因子库版本、规则版本与计算指纹摘要。
- 权限与脱敏的**呈现层**执行：按当前角色隐藏或遮蔽字段（判定逻辑归属合规内建）。

**不做什么**

- 不实现核算公式、因子选择、分摊逻辑——归属 `modules/calculation/README.md`。
- 不直连数据库细节：不写 SQL、不持有表结构；持久化经契约访问。
- 不做正式数值判定，不替 AI 输出背书，不替人工确认做决定。
- 不做数据包内容定义——归属 `modules/data_package/README.md`。

## 模块接入方式

1. 模块实现 `contracts/README.md` 中声明的接口与数据类型。
2. 模块向 `startup/` 的注册表声明自身标识、依赖项、要求的字典/规则版本。
3. 外壳只通过契约调用模块，模块**不得**跨模块引用内部数据结构。
4. 模块视图在 `shell/` 中挂载；模块不得直接操作导航容器或全局状态。

## 目录约定

| 路径 | 职责 | 边界 |
| --- | --- | --- |
| `app/startup/` | 配置加载、日志、存储与知识库就位、模块注册、健康自检 | 不含界面代码 |
| `app/shell/` | 主窗口、导航、工作台视图、状态与错误呈现 | 不含启动与注册逻辑 |

约定：`startup/` 先于 `shell/` 完成；`shell/` 只消费 `startup/` 暴露的已就绪运行时。

## 验收要点

- [ ] 能在完全离线环境下完成启动并进入工作台。
- [ ] 任一模模块缺失或版本不匹配时，外壳给出可读提示且不整体崩溃。
- [ ] 外壳代码中检索不到核算公式、因子取值等业务判定。
- [ ] 界面任意处显示的数值均可追溯到某次 `CalculationRun` 的指纹。
