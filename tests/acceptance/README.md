# 验收测试（tests/acceptance）

> 状态：首期骨架

本目录从**用户与评审视角**验证产品是否达到可交付标准：走完整业务流程、跑完四组对照实验、
产出可复核的结论与演示材料。验收测试的判定依据必须来自 `tests/fixtures/` 的基准数据与容差声明。

## 一、完整业务流程验收

一条端到端路径，覆盖产品三层能力：

| 步骤 | 验收要点 |
| --- | --- |
| 1. 建立产品与功能单位 | `Product` 信息完整，功能单位与边界明确 |
| 2. 导入 BOM 与工序 | 数据可导入、可纠错，问题行有定位提示 |
| 3. AI 副驾驶给出映射候选 | 候选附依据与置信度，**不产生正式核算数值** |
| 4. 人工确认 | 确认结果留痕，可追溯到人与时间 |
| 5. 确定性核算 | 规则约束下计算，同一输入 → 同一结果，结果带版本与指纹 |
| 6. 数据审核 | 字段完整率达标，异常有明确处置记录 |
| 7. 导出数据包 | `DataPackage` 结构合法、可被重新解析并复算 |

## 二、四组对照实验

| 实验 | 主题 | 记录指标 | 判定方式 |
| --- | --- | --- | --- |
| A | AI 匹配 | Top-1 命中率、Top-3 命中率、人工修正率 | 与基准映射逐一比对，按基准声明的容差判定 |
| B | 资源分摊 | 分摊差异、敏感性 | 分摊前后守恒；参数扰动下结果变化幅度在容差内 |
| C | 流程效率 | 人工 Excel 处理时间与工具处理时间、错误率 | 同一批脱敏样例，记录耗时与错误数 |
| D | 可审计性 | 复算一致率、字段完整率 | 重复复算结果一致；必填字段全部齐备 |

> 实验 A/B 的输入输出必须由 `tests/fixtures/` 承接：fixture 中同时给出输入数据与期望结果（含容差）。
> 实验 C 的耗时数据属于**过程记录**，须在测试报告中记录采集方式与机器环境，不得事后估算。
> 指标口径的最终定义【待确认】，确定后同步更新本文件与 [../fixtures/README.md](../fixtures/README.md)。

## 三、结题演示脚本

验收测试同时充当**结题演示脚本**的执行者，演示顺序建议：

1. 用脱敏样例库演示 BOM → 工序映射，展示 AI 候选与人工确认；
2. 演示确定性核算：同一输入连续两次运行，展示结果指纹一致；
3. 展示数据包导出物，并用其复算，展示复算一致率；
4. 展示四组对照实验的结果表与结论；
5. 展示审计链：谁在何时确认了什么、依据是哪条规则或哪份因子。

演示材料中禁止出现真实企业料号、客户名与价格；`docs/product/` 下的计划书与答辩 PPT 由人工维护。

## 四、约定

| 项目 | 约定 |
| --- | --- |
| 判定依据 | 只认 fixture 中声明的期望结果与容差，不认"看起来差不多" |
| 可重复 | 每次验收运行须记录：基准版本、代码版本、运行环境、时间 |
| 失败处理 | 验收失败必须定位到具体步骤与具体指标，不得只写"未通过" |
| 数据 | 全部使用脱敏样例；真实企业数据不得进入验收与演示 |
| 报告 | 结果以表格呈现，附原始输出与退出码 |
