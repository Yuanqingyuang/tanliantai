# 工作流：发布

> 状态：草案

适用：打标签、对外交付碳数据包、提交结题与答辩材料。发布的对象有三类，其版本节奏不同，必须分别管理。

## 0. 发布对象与版本线

| 对象 | 版本载体 | 说明 |
| --- | --- | --- |
| 工具原型 | 产品版本号 | 可运行工具的能力与行为 |
| 碳数据包规范 | 规范版本号 | 字段、口径、缺口与质量等级、指纹与修改记录 |
| 工序活动数据字典 | 字典版本号 | PCBA-SMT 工序级字段口径 |
| 知识与因子 | 公式/因子登记表版本 | 影响核算结果的取值与规则 |
| 结题/答辩材料 | 冻结包（不单独编号） | 一次性冻结，与上述版本对应 |

## 1. 版本号规则

采用 `主版本.次版本` 两段式（示例：`V1.0`），含义如下：

| 变更类型 | 版本动作 | 判定 |
| --- | --- | --- |
| 破坏性变更（字段删除/改名、单位口径改变、指纹算法改变、边界调整） | 主版本 +1 | 旧数据包可能无法直接复算或比对 |
| 向后兼容的字段新增、新增可选校验、文档澄清 | 次版本 +1 | 旧数据包仍可读 |
| 纯文案与排版修正 | 不升版，记 CHANGELOG | 不影响口径 |

关键约束：

- **核算口径变更必须升版**，且同时升"因子/规则版本"，即使工具代码未变。
- 版本号一旦对外使用不得复用；发现错误时以新版本修正，并说明旧版本处理策略。
- 当前起点版本：数据字典 V0.1、数据包规范 V0.1（里程碑"数据字典与架构"阶段的计划产物）；V1.0 为成果固化阶段目标【待确认】具体升版条件由项目负责人确认。

## 3. CHANGELOG 更新要求

[CHANGELOG.md](../../CHANGELOG.md) 采用 [Keep a Changelog](https://keepachangelog.com/zh-CN/1.1.0/) 的分组写法：开发中的改动记入 `[Unreleased]`，发布时整理为版本段落，段落内按 `新增 / 变更 / 修复 / 弃用 / 移除`（另可含 `计划中 / 已知缺口`）分组。

每条记录至少写清"用户可见影响"；凡属**口径变更**，还必须写清：

| 字段 | 内容 |
| --- | --- |
| 用户可见影响 | 对使用者的行为或数据意味着什么 |
| 口径影响 | 是否改变核算结果；若改变，说明因子/规则版本 |
| 迁移说明 | 旧数据包是否需要重算、如何比对 |
| 依据 | 指向登记表条目或标准/文献标识（不写页码臆测） |

## 4. 数据包规范版本管理

- [ ] 规范版本记录在数据包内，可与工具版本分别追溯
- [ ] 数据包内携带：核算结果与活动数据、因子来源与版本、数据缺口与质量等级、修改记录与字段映射、计算指纹
- [ ] 新旧版本数据包的差异比对方式已说明
- [ ] 若字段语义变化但名称不变，必须有显式的语义变更说明

## 5. 结题与答辩材料冻结

- [ ] 冻结清单：研究报告、软著材料、数据字典 V1.0、数据包规范 V1.0、评测数据集与案例集、商业计划书
- [ ] 所有图表与数字均可回溯到登记表或评测记录，禁止"口径不同的数字混用"
- [ ] 冻结后修改必须走本流程重新冻结，并保留上一冻结版本
- [ ] 演示用数据一律使用脱敏示例；演示过程不出现可识别企业信息
- [ ] 对外承诺的指标口径与评测报告一致，未经验证的结论不写入材料
