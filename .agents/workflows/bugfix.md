# 工作流：缺陷修复

> 状态：草案

适用：结果不符、程序报错、字段错位、单位错误、复算不一致、界面数据与数据包不一致。核心要求：**先复现，后修复；修复必须可回归验证**。

## 0. 分级

| 级别 | 判定 | 处理要求 |
| --- | --- | --- |
| P0 核算正确性 | 核算结果、单位、边界、因子取值错误，或同输入结果不一致 | 立即停止对外交付，按 [`calculation-change.md`](calculation-change.md) 处理 |
| P1 数据完整/安全 | 数据丢失、越权可见、日志缺失、真实企业数据外泄风险 | 按 [`.agents/policies/data-security.md`](../policies/data-security.md) 立即处置 |
| P2 功能阻断 | 关键路径不可用（导入 BOM、确认候选、导出数据包失败） | 当日修复并回归 |
| P3 一般缺陷 | 展示、文案、次要交互 | 排期修复 |

## 1. 复现

- [ ] 记录最小复现输入（使用 [`tests/fixtures/README.md`](../../tests/fixtures/README.md) 的基准数据；不得使用未脱敏企业数据）
- [ ] 记录预期与实际结果，含字段名、单位、数值
- [ ] 记录触发条件：输入规模、映射方式、因子版本、分摊方法
- [ ] 无法复现时标注「【待确认】无法复现」，说明需要谁提供环境或样本

## 2. 定位

排查顺序建议（自上而下排除）：

1. 输入侧：BOM 字段是否错位、单位是否一致、活动数据是否缺失
2. 映射侧：BOM→工序映射是否正确、人工确认记录是否存在
3. 因子侧：来源、区域、版本、单位四重校验是否通过
4. 规则侧：边界、单位、分摊规则是否被绕过
5. 计算侧：公式实现与 [`knowledge/formulas/formula-register.md`](../../knowledge/formulas/formula-register.md) 是否一致
6. 输出侧：数据包字段与 [`contracts/README.md`](../../contracts/README.md) 是否一致

定位结论必须写明"根因是什么、为什么会漏过现有测试"。

## 3. 修复

- [ ] 修复范围最小化，不做与缺陷无关的重构
- [ ] 触及核算口径（公式/因子/边界/分摊）时，改走 [`calculation-change.md`](calculation-change.md)，不得直接改数值
- [ ] 新增或更新测试用例，使该缺陷在测试中可被捕获
- [ ] 若原基准数据本身有误，按 [`.agents/policies/boundaries.md`](../policies/boundaries.md) 的基准数据改动规则处理并登记

## 4. 回归

- [ ] 该缺陷的专属用例通过
- [ ] 同模块全部 unit / integration 用例通过
- [ ] 确定性回归：同输入同结果、结果指纹符合预期（变化则说明原因）
- [ ] P0/P1 缺陷需提供"修复前 / 修复后"对照记录
- [ ] 抽查受影响的数据包产物字段完整率与复算一致率

## 5. 记录

在交付报告（[`templates/delivery-report.md`](../templates/delivery-report.md)）中至少包含：

| 项 | 内容 |
| --- | --- |
| 缺陷描述 | 现象、影响面、级别 |
| 复现输入 | 数据来源与关键参数 |
| 根因 | 触发链条与漏测原因 |
| 修复方案 | 改动点与为何最小 |
| 验证结果 | 用例名、执行结果、供证据的命令/记录 |
| 影响评估 | 是否影响已交付结果或历史数据包；若影响，给出重算范围 |
| 遗留 | 未解决问题与「待确认」项 |

## 6. 预防

- [ ] 是否为同类缺陷补充规则约束（异常检测、范围校验、四重校验）
- [ ] 是否需要在 [`docs/development/README.md`](../../docs/development/README.md) 增加排错条目
- [ ] 是否为反复出现的缺陷提升测试层级（unit → integration / acceptance）
