# 工作流：审查

> 状态：草案

适用：合并前自审与互审、对外交付前审查、结题与答辩材料审查。审查以四个视角独立进行，**每个视角单独给出结论**，不得互相替代。

## 0. 通用前置

- [ ] 审查对象明确（文件清单、版本、范围）
- [ ] 已读 [`AGENTS.md`](../../AGENTS.md) 与 [`context-map.md`](../context-map.md) 中对应任务类型
- [ ] 审查者已确认自己不是改动者（涉及核算口径时不得自审）
- [ ] 结论格式：`通过` / `有条件通过（列出条件）` / `退回（列出原因）`

## 1. 代码审查

| 检查项 | 判定要点 |
| --- | --- |
| 契约一致性 | 字段名、类型、单位、必填性与 [`contracts/README.md`](../../contracts/README.md) 一致 |
| 边界遵守 | 改动未越过 [`policies/boundaries.md`](../policies/boundaries.md) |
| 确定性 | 同输入同结果；无隐藏随机性、无依赖时间的隐式行为 |
| 指纹 | 结果指纹生成与变更逻辑正确，历史版本可比对 |
| 三层分离 | 无 "AI 输出直接作为核算数值" 的路径 |
| 规则约束 | 单位、范围、必填校验存在且不可绕过 |
| 错误处理 | 数据缺失、字段错位、因子缺失时给出明确提示而非静默使用默认值 |
| 安全性 | 权限校验、脱敏、日志按 [`.agents/policies/data-security.md`](../policies/data-security.md) 落实 |
| 测试 | 分层测试齐备，含回归与复算一致性用例 |

## 2. 文档审查

- [ ] 结论与依据一一对应，可回溯到标准、文献或登记表
- [ ] 无未标注来源的数字；不确定项均以「【待确认】+ 需确认人」形式呈现
- [ ] 术语与 [`knowledge/README.md`](../../knowledge/README.md) 一致
- [ ] 范围与非目标清晰，未夸大成果（不承诺未经验证的指标）
- [ ] 文档间引用路径真实存在，无失效链接
- [ ] 用户可见行为变化已进入 [`docs/development/README.md`](../../docs/development/README.md) 与 `CHANGELOG.md`
- [ ] 里程碑表述与 [`docs/planning/README.md`](../../docs/planning/README.md) 一致

## 3. 知识与依据审查

- [ ] 公式变更已在 [`knowledge/formulas/formula-register.md`](../../knowledge/formulas/formula-register.md) 登记，含变量、单位、适用边界、依据
- [ ] 因子变更已在 [`knowledge/emission-factors/factor-register.md`](../../knowledge/emission-factors/factor-register.md) 登记，来源/单位/区域/版本四项完备
- [ ] 因子快照随结果留档，核算结果可追溯到当时因子版本
- [ ] 对照案例复算记录完整，差异有解释
- [ ] 单位换算链显式且唯一，无隐式换算
- [ ] 无引用失效、无张冠李戴的标准条款引用
- [ ] 核算口径变更是否经人工确认（谁、何时、确认内容）

## 4. 数据安全审查

- [ ] 仓库中不存在真实企业 BOM、工艺、价格、客户名、料号可识别信息
- [ ] 示例数据均已脱敏，且保留"可核验结构、不可还原实体"的性质
- [ ] 截图、演示材料、答辩 PPT 中的料号/客户/价格已处理
- [ ] 权限为最小必要；敏感字段访问有日志
- [ ] 本地部署选项的说明与实际能力一致
- [ ] 访问与操作日志可支持事后追溯（谁在何时读写/导出/修改了什么）
- [ ] 无真实数据被写入 [`data/examples/`](../../data/examples/README.md) 或 [`tests/fixtures/`](../../tests/fixtures/README.md)

## 5. 审查输出模板

| 字段 | 内容 |
| --- | --- |
| 审查对象 | 文件清单 / 变更范围 |
| 视角结论 | 代码 / 文档 / 知识与依据 / 数据安全 各自结论 |
| 发现问题 | 按 P0—P3 分级，给出定位与建议 |
| 必需修改项 | 合入前必须完成的条目 |
| 建议项 | 可后续处理，需登记待办 |
| 未决 | 「待确认」项与确认人 |
| 总体结论 | 通过 / 有条件通过 / 退回 |

## 6. 退回后的处理

- 退回项整改后**重新审查**，不得由改动者自行宣布通过。
- P0（核算正确性）与 P1（数据安全）退回项必须由非改动者复核并留痕。
