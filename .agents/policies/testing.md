# 策略：测试

> 状态：草案

目的：保证"确定性核算 + 可审计数据包"这两个核心承诺可被持续验证。测试不是事后补充项，而是核算类改动的合入门槛。对应 `AGENTS.md` 规则 R2、R3、R8、R9。

## 1. 四层职责

| 层级 | 位置 | 职责 | 不负责 |
| --- | --- | --- | --- |
| unit | 单元测试目录 | 字段校验、单位换算、范围规则、分摊公式、指纹生成的纯逻辑正确性 | 跨模块链路、真实文件导入 |
| integration | 集成测试目录 | BOM→工序映射、因子选取与四重校验、规则约束 → 人工确认 → 计算 → 结果落库链路、权限与日志联动 | 完整交付形态评价 |
| acceptance | 验收测试目录 | 端到端产出碳数据包：字段完整性、缺口与质量等级、修改记录与字段映射、指纹可复算 | 内部实现细节 |
| fixtures | [`tests/fixtures/`](../../tests/fixtures/README.md) | 可复用的基准输入与期望结果，保证结果可比、可回放 | 存放真实企业数据 |

配套数据集：A 组对照实验（AI 匹配 Top-1/Top-3/人工修正率）、B 组（资源分摊结果差异与敏感性）、C 组（流程效率：处理时间、步骤数、错误率）、D 组（可审计性：复算一致率、字段完整率）所需的评测数据与案例集，其基准输入统一由 `tests/fixtures/` 管理。

## 2. 分层最低要求

| 层级 | 最低要求 |
| --- | --- |
| unit | 每条规则约束（单位、范围、必填、异常判定）至少一个正例与一个反例 |
| unit | 单位换算必须成对测试，含边界值与非法单位拒绝 |
| integration | 至少覆盖：字段错位、活动数据缺失、因子缺失或不匹配区域/版本、映射需人工确认 |
| integration | AI 相关链路只断言"输出候选、依据、置信度"，并断言**不产生正式核算数值** |
| acceptance | 同一份输入连续运行两次，结果与指纹完全一致 |
| acceptance | 数据包必须包含：核算结果与活动数据、因子来源与版本、数据缺口与质量等级、修改记录与字段映射、计算指纹 |
| fixtures | 每个基准案例注明来源、构造方式、预期结果与适用工序 |

## 3. 确定性核算的强制测试

| 测试 | 内容 | 触发时机 |
| --- | --- | --- |
| 架构不变量 | 智能层（AI）输出**永不进入**核算输入路径：核算的每个输入数值都必须可回溯到已登记的因子与活动数据，AI 候选只能经人工确认后以规则形式进入（R2 的机器可验证形式） | 每次改动智能层或核算层 |
| 回归测试 | 已知输入 → 冻结的期望结果与指纹；任何漂移即失败 | 每次改动核算相关代码 |
| 复算一致性 | 同一 `CalculationRun` 输入可重放出相同结果与指纹 | 每次改动计算层或规则层 |
| 因子快照追溯 | 用历史因子版本重放旧结果，结果不变 | 因子登记表变更时 |
| 口径变更对照 | 改动前/后结果差异对照案例，差异有解释 | 走 [`calculation-change.md`](../workflows/calculation-change.md) 时 |
| 顺序无关性 | 输入条目的排列顺序不影响总量（除显式声明顺序相关者） | 计算层改动 |
| 分摊敏感性 | 产量法/设备时间法/贴片点数法/多因素法下的结果区间可复现 | 分摊方法或参数变更 |

失败即阻断：架构不变量、回归、复算一致性、因子快照追溯四类测试失败时不得合入、不得对外交付。

## 4. 基准数据规则

- [ ] 基准数据一律脱敏，可在无企业数据环境独立运行
- [ ] 基准取值变更视同核算口径变更，需独立理由与人工确认（见 [`boundaries.md`](boundaries.md)）
- [ ] 禁止通过修改期望值使失败用例通过
- [ ] 新增基准须在 [`tests/fixtures/README.md`](../../tests/fixtures/README.md) 登记

## 5. 覆盖率目标

- 覆盖率目标与判定阈值【待确认】：需由项目负责人与指导教师确认（候选口径：核算层核心规则行覆盖优先于全局行覆盖比例）。
- 在目标确认前，执行临时约定：**凡新增或修改的核算规则分支必须被测试覆盖，且不存在仅由人工验证的核算逻辑**。
- 覆盖率不作为唯一质量指标；核算正确性与可复算性优先。

## 6. 测试执行与证据

| 项 | 要求 |
| --- | --- |
| 执行方式 | 统一命令或脚本；命令需登记在 [`docs/development/README.md`](../../docs/development/README.md) |
| 证据留存 | 记录用例名、执行时间、结果、失败原因；核算类测试保留对照数值 |
| 环境 | 环境依赖登记在 [`environment/README.md`](../../environment/README.md) |
| 无法执行的测试 | 在交付报告中明确标出缺口、原因与补齐计划，不得默认通过 |

## 7. 自检清单

- [ ] 本次改动是否有对应层级的新增/更新用例
- [ ] 是否包含同输入同结果的确定性验证
- [ ] 因子或规则是否携带版本参与验证
- [ ] 数据包字段完整性是否被断言
- [ ] 是否误用了真实企业数据作为测试输入
