# 策略：数据安全

> 状态：草案

适用对象：企业 BOM（物料清单）、工艺参数、设备与工时记录、辅材用量、供应商与客户信息、价格信息。这些数据属**敏感商业数据**，是中小供应商的核心资产。本策略对应 `AGENTS.md` 规则 R4。

## 1. 数据分级与本项目应对

| 级别 | 数据 | 处理要求 |
| --- | --- | --- |
| L1 公开 | 标准号、公开因子来源说明、品牌与公开材料 | 可自由写入仓库 |
| L2 内部 | 数据字典、规则、示例结构 | 可入库，但不得包含可识别实体信息 |
| L3 敏感 | 企业 BOM、工艺路线、活动数据、产能与价格 | **禁止入库**；仅在受控运行环境内处理 |
| L4 敏感聚合 | 多企业数据汇总、可比对结果 | 需最小权限 + 脱敏 + 留痕；对外仅出聚合口径 |

判定原则：不确定级别时按更高级别处理。

## 2. 最小权限

- [ ] 按角色授予必要字段与必要操作（查看/编辑/导出/删除分离）
- [ ] 导出为独立受控操作，需留痕并说明用途
- [ ] 默认拒绝：未显式授予的能力不可用
- [ ] 权限变更本身需留痕
- [ ] 具体角色划分与鉴权技术方案【待确认】：由项目负责人在 ADR 中确定

## 3. 脱敏

- [ ] 示例数据必须脱敏后再入库：去除料号可识别信息、客户与供应商名称、价格、联系人、企业名
- [ ] 脱敏保留可核验结构（字段形态、单位、工序类型），但不可还原到具体实体的真实字段值
- [ ] 禁止用"改几个字符"的方式处理真实数据；应重建结构
- [ ] 截图、演示、答辩材料中的料号/客户/价格一并处理
- [ ] 脱敏后的示例数据存放于 [`data/examples/`](../../data/examples/README.md) 并说明构造方式
- [ ] 脱敏检查纳入 [`review.md`](../workflows/review.md) 的数据安全审查视角

## 4. 本地部署选项

- [ ] 保留本地部署路径，使企业数据不出企业边界即可完成数据准备与核算
- [ ] 本地部署所需的能力边界（哪些能力在离线/内网可用）需在 [`environment/README.md`](../../environment/README.md) 说明
- [ ] 涉及外部调用的功能（如 AI 候选匹配）必须支持关闭或替换为本地能力，关闭后核心核算链路仍可运行
- [ ] 外部调用时的数据范围需最小化：优先上传结构信息而非原始 BOM 全量【待确认】具体脱敏上传策略由 ADR 决定
- [ ] 对外部服务的数据使用条款与留存策略需人工确认后再启用

## 5. 日志与留痕

必须记录并可追溯：

| 记录项 | 内容 |
| --- | --- |
| 访问日志 | 谁、何时、读取了哪类数据 |
| 操作日志 | 导入、编辑、确认、计算、导出、删除 |
| AI 候选留痕 | 模型版本、候选列表、依据、置信度 |
| 人工确认留痕 | 确认人、确认对象、确认结果 |
| 计算结果留痕 | 规则版本、因子版本、结果指纹 |
| 变更记录 | 字段映射与修改记录（随数据包交付） |

- [ ] 日志不可被普通使用者删除或篡改
- [ ] 日志本身不得包含超出必要的敏感明文
- [ ] 日志保留期与导出权限【待确认】：由项目负责人确认

## 6. 禁止事项（硬性）

- 禁止把真实企业数据提交进 Git（含示例目录、测试基准、附件、截图）
- 禁止把真实数据粘贴进任务说明、交付报告、Issue、聊天记录或外部服务
- 禁止在答辩与演示中使用真实企业数据
- 禁止将含敏感字段的日志或数据包发送到未受控的第三方存储
- 禁止为"方便调试"临时把真实数据写入仓库文件后不清理

## 7. 泄露应急预案

1. 立即停止相关操作，记录发现时间与现象。
2. 确认暴露范围（文件、提交、外部服务、材料）。
3. 立即上报项目负责人与指导教师，由负责人决定通知与补救方式。
4. 在交付报告中如实记录事件、范围、处理与改进措施；不得隐瞒。
5. 复盘并补充检查项到本策略或 [`review.md`](../workflows/review.md)。

## 8. 自检清单

- [ ] 我写入仓库的每个数据文件都可公开（无真实实体信息）
- [ ] 示例数据为重建的脱敏结构，非真实数据轻改
- [ ] 我执行的操作有日志可查
- [ ] 我未把敏感数据带入文档、截图或对外材料
- [ ] 关闭外部能力后核心核算链路仍可用
