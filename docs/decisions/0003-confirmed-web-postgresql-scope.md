# 0003 Web与PostgreSQL申报方案确认
> 状态：已接受（用户确认的申报与后续验证方向）
> 日期：2026-10-28
> 决策来源：当前会话用户明确提出的四项约束。指导教师与学校审批不由本记录替代。

## 背景与问题
ADR0002及前一版技术建议尚将Web、数据库与模型调用边界列为提议。用户现已明确应用形态、技术栈、内网多用户及数据出域边界，需要在新版申请书中统一口径。

## 备选方案
Web浏览器客户端便于内网多用户，桌面壳需要额外打包与进程管理，留待后续；PostgreSQL与MySQL均具有关系数据与精确数值能力，本次按用户确认采用PostgreSQL，首期不维护双数据库；外部API便于开发验证，本地模型保证真实企业数据留在内网，采用可替换接口控制使用边界。

## 决策
1. 首期采用Web客户端，桌面壳后置。
2. Vue 3 + TypeScript、FastAPI、PostgreSQL。PostgreSQL选型已确认，兼容性/事务/精度/迁移/并发/备份恢复验证由T-0010完成，当前不得标为已通过。
3. 面向企业内网多用户；首期包含项目管理员、数据录入员、核算复核员和只读审阅员四类角色，以及服务端权限、会话、HTTPS和审计。
4. 开发期云端API仅处理非敏感数据；真实企业数据本地处理。预留AIProvider，外部能力可关闭或替换，正式计算不依赖生成式模型。

## 理由与后果
统一浏览器交互和Python研究链路，降低重复实现成本；安全能力是首期部署条件。仅替代ADR0002中与上述四项冲突的提议状态，不批准其余具体模型版本、数据包schema、核算精度或分摊规则。

## 影响范围
本次落实到申请书、决策索引与文档留痕；后续实现仍须契约先行。没有数据库或应用实现迁移，没有完成T-0010。

## 复核条件
T-0010发现兼容性或资源约束、部署环境发生变化、真实数据本地处理能力不足时，记录证据并由负责人重审。数据包与核算口径继续按独立规则评审。
