# 链碳台：详细技术方案与项目申报内容建议稿
> 状态：草案

编写日期：2026-10-27。项目名称沿用“链碳台：面向 PCBA-SMT 的工序级碳数据智能准备与核算方法研究”。本稿覆盖技术方案、国内外研究现状、创新点、技术路线、研究进度、前期积累、研究条件和预期成果八部分。

技术选型属于 [ADR 0002 提议](../decisions/0002-proposed-local-web-stack.md)，尚未成为已批准实施基线。进度与已有数量目标沿用原计划书。研究成效均为待验证目标，正式核算口径仍须经标准正文、登记表和人工复核确认。本稿不启用任何新公式、因子或默认分摊方法。

## 一、重新设计的详细技术方案

### 1.1 建设目标与交付闭环

本项目拟建设面向中小电子制造企业的 PCBA-SMT 碳数据准备与核算研究原型，接收企业已有 BOM、工艺路线、设备运行和能源辅材记录，将分散表格转化为结构化、可复核的产品碳数据。系统重点解决“数据怎么整理、候选怎么确认、结果怎么计算、依据怎么交付”四类问题。

首期以一个明确规格的 PCBA 产品及其实际工序链为验证对象，跑通“建立核算任务—导入数据—字段与语义归一—人工审核—规则校验—确定性计算—结果分析—数据包导出—独立回放”的闭环。BOM 本身不能唯一推导企业实际工艺路线，系统必须结合工艺记录和人工确认建立关系。

研究分两步验证：先验证 SMT 制造阶段数据处理与计算链路，再在上游材料等数据充分时验证项目确定边界内的产品碳足迹。只有制造阶段数据时，报告应明确所覆盖阶段和缺口；不能将其包装为完整生命周期结论。边界、参考单位、运输纳入和截断规则由核算负责人依据适用标准及具体产品要求确认，本稿不预设为正式规则。

### 1.2 总体架构与应用形态

推荐采用“本地部署、浏览器访问、前后端分离、模块化单体”的架构。用户在浏览器中操作工作台，数据处理、核算、模型推理和存储在本机或企业内网服务完成。Web 形态描述的是操作方式，不意味着企业数据必须上传互联网。

系统分为四层：应用层负责导入、编辑、审核和展示；业务服务层负责项目、工艺、数据质量、版本和任务编排；智能辅助层负责候选检索与解释；确定性核算及数据层负责规则计算、快照和数据包。智能层不能绕过确认接口写入正式核算输入。

```text
Excel / CSV / 工艺记录
        ↓
导入暂存区 → 字段映射与单位校验 → 数据缺口清单
        ↓
物料、工序、活动数据与已复核因子
        ↓
规则检索 + 语义检索 → 候选与来源 → 人工确认
        ↓
冻结输入、规则和因子版本 → 确定性核算引擎
        ↓
分项结果、质量与缺口 → 数据包 → 独立校验与回放
```

采用单一后端工程按领域划分模块，减少学生团队的部署和接口维护负担。首期不建设微服务集群、区块链、在线交易平台或全厂物联网系统。设备数据先通过文件导入与人工录入获取，后续有条件再设计 MES 或计量设备适配器。

### 1.3 语言、框架和工具选型

下表为推荐组合。版本应在首次集成时验证并锁定，不使用“永远跟随最新版”的依赖方式。

| 层次 | 推荐语言/框架/工具 | 具体用途与选择理由 |
| --- | --- | --- |
| 前端 | TypeScript、Vue 3、Vite | 建设数据表格和多步骤审核工作台；延续原计划书方向，明确接口类型 |
| 交互组件 | Element Plus、Vue Router、Pinia | 表格、表单、导航和界面状态；正式数值仍由后端返回 |
| 图表 | Apache ECharts | 展示物料/工序贡献、分摊差异和敏感性，不在图表层重新核算 |
| 后端 | Python、FastAPI | 统一数据处理、实验与接口开发，支持 OpenAPI 接口描述 |
| 数据校验 | Pydantic、JSON Schema | 实体输入校验和数据包结构校验；字段语义仍由项目契约定义 |
| 数据库 | PostgreSQL | 存储实体、确认关系和版本；NUMERIC 保存核算数值，JSONB 保存结构化快照 |
| 数据访问 | SQLAlchemy、Alembic | 数据访问、事务与数据库迁移；避免在多个模块散落 SQL 和改表脚本 |
| 文件处理 | pandas、openpyxl、Python csv | 读取 Excel/CSV、字段整理、模板导出；正式核算值绕开浮点化的数据通道 |
| 确定性计算 | Python Decimal、经登记的单位转换表 | 固定精度、舍入和运算次序，依据复核规则计算 |
| 智能检索 | Sentence Transformers、本地嵌入模型 | 对物料描述、工序名称和因子条目做语义候选检索 |
| 模型候选 | BAAI/bge-m3 | 作为中英混合语义检索的候选基线；效果和资源需求须在本项目数据上验证 |
| 检索索引 | 首期精确相似度检索；需要时引入 FAISS 或 pgvector | 先测量语料规模、响应时间与内存，再增加索引组件 |
| 可读报告 | Jinja2、HTML；openpyxl 导出 Excel | 提供可读摘要与表格；PDF 可先通过浏览器打印，权威数据仍保存在结构化文件中 |
| 文件证据 | 本地受控目录 + 数据库元数据 | 保存原文件、快照和证据清单；文件目录位于 Git 仓库之外 |
| 测试 | pytest、Hypothesis、Vitest、Playwright | 分别覆盖规则/性质测试、前端组件和端到端审核流程 |
| 开发与部署 | Git、现有 GitHub Actions、Docker Compose | 复用现有协作设施；固定 Python/Node/数据库依赖与镜像，提供安装和恢复说明 |

Vue 官方提供 TypeScript 与组件化开发路径，FastAPI 提供基于 OpenAPI 的接口与数据校验支持，这些能力适合本项目的数据审核界面与接口管理。[Vue 官方文档](https://vuejs.org/guide/introduction.html)、[FastAPI 官方文档](https://fastapi.tiangolo.com/features/)。

PostgreSQL NUMERIC 和 Python Decimal 能支持十进制数值处理，但“同输入同结果”仍需额外固定精度、舍入、规则版本和计算次序。[PostgreSQL 数值类型](https://www.postgresql.org/docs/current/datatype-numeric.html)、[Python Decimal](https://docs.python.org/3/library/decimal.html)。

原计划书中的 MySQL 也能满足核心关系数据与精确小数存储需求。本稿推荐 PostgreSQL，主要考虑结构化快照和未来检索扩展的统一管理，并非 MySQL 不能实现。若团队已熟练掌握 MySQL，应在选型评审中优先衡量学习成本，避免为更换数据库推迟研究。

### 1.4 模块设计与主要页面

| 模块 | 输入与处理 | 输出与页面 |
| --- | --- | --- |
| 项目与产品 | 产品规格、核算期间、研究边界、参考单位与责任人 | 项目总览、任务状态、范围声明 |
| BOM 导入 | Excel/CSV、表头映射、单位识别、原始行定位、错误检查 | 导入预览、错误行、待确认字段 |
| 工序与设备 | 实际工艺路线、设备和资源关系；模板仅提供候选节点 | 工序链编辑、各工序数据需求清单 |
| 数据字典 | 字段定义、单位、来源、可空性、版本 | 字典管理、模板说明、字段帮助 |
| 活动数据 | 电量、辅材、工时、产量、期间和计量对象 | 数据录入、来源等级、缺口与异常任务 |
| 因子管理 | 来源、数值、单位、时间、区域、适用边界与许可 | 待复核/已复核条目、版本差异、来源查看 |
| 智能候选与审核 | 规则和语义检索、约束过滤、候选解释 | 候选对比、确认/拒绝/手工选择、理由留痕 |
| 确定性核算 | 经确认的快照、已复核规则和因子 | 逐项计算明细、任务失败原因、结果版本 |
| 结果分析 | 工序和物料贡献、可比较情景 | 贡献图、差异表、边界不一致提示 |
| 数据包与审计 | 结果、输入、来源、版本、操作记录和附件许可 | 导出预检、数据包下载、回放与一致性检查 |

界面主流程建议按“项目—导入—工序—数据补齐—候选审核—计算—分析—交付”组织。用户应能从异常定位回原始行，从结果定位到活动量、因子、规则与确认记录。

### 1.5 数据与接口设计

继续使用既有八类核心实体：Product、BOMItem、Process、ActivityData、EmissionFactor、Mapping、CalculationRun、DataPackage。关系设计为：产品关联 BOM 和工序链，工序关联活动数据；Mapping 保存候选与确认；CalculationRun 引用不可变的输入、因子和规则快照；DataPackage 引用一次具体计算及其证据。

接口按业务动作划分为导入预检、提交数据、获取候选、确认映射、预检计算、启动计算、查询结果、生成数据包和回放验证。具体字段名、类型和版本应先落入 contracts，再生成前后端接口，避免以界面临时字段代替正式契约。

关键设计要求如下：

1. **原始值与标准值并存。** 保留文件指纹、工作表和行号、原始单位、标准单位及转换依据，所有纠错保留前后值。
2. **未知不能填零。** 缺失量、真实零值和不适用分别表达；必需数据缺失时阻止生成正式计算结果。
3. **时间范围明确。** 保存数据覆盖期间与计量对象，同一计量来源的重叠数据不能重复入账。
4. **确认绑定版本。** 修改了描述、单位、因子或工序后，旧确认失效并要求重审；不能用旧确认覆盖新输入。
5. **快照不可覆盖。** 新核算形成新版本，旧结果仍能指向当时数据；草稿与已冻结数据分开管理。
6. **精确小数贯通。** API 和权威 JSON 中以规范小数字符串传递正式数值；数据库采用精确数值类型。Excel 中的计算公式不自动执行，只有缓存结果时应提示来源局限。

### 1.6 AI 候选匹配方案

研究流程为“规则归一—候选召回—约束过滤—排序与解释—人工确认”。首先按词典整理缩写、封装和单位；再以规则关键词和本地嵌入向量检索候选；对单位、材料类别、区域、年份、边界等条件进行筛选。若不存在适用候选，返回“需补充数据/需人工检索”，不能强行选一个最相似条目。

Sentence Transformers 的语义检索工具适合建立可重复的检索基线；BGE-M3 的模型卡提供了多语言检索能力和使用方式，但通用模型能力不等于已经适配 PCBA，必须做独立评测。[语义检索文档](https://www.sbert.net/examples/sentence_transformer/applications/semantic-search/README.html)、[BGE-M3 模型卡](https://huggingface.co/BAAI/bge-m3)。

区分三类任务分别计分：字段名映射、物料类别归一、因子候选选择。BOM 到工序关联需工艺证据，不把所有物料简单归到“贴片”节点。对于同类元器件、不同封装或不同制造技术造成的相似描述，应保留拒答和歧义状态。

候选展示名称、来源、适用条件、匹配依据、冲突项和得分。相似度只表示排序相关性，未经校准不能展示为“正确概率”。置信度分级阈值在开发集确定，独立测试集仅作最终评价。

生成式模型可作为解释增强项，读取已检索的有限证据后生成说明；引用对象必须来自候选集合。模型无权生成因子值、补写标准条款或调用正式写入接口。保存模型版本、检索库版本、提示模板和候选记录。基础流程在模型关闭时仍能通过规则检索与人工录入完成。

### 1.7 确定性核算方案

核算引擎采用独立 Python 领域模块，接收冻结快照，返回分项结果和检查记录，不依赖在线模型、当前时间或会变化的外部数据库。正式运算仅调用登记且已复核的规则与因子；目前仓库登记表仍为草案或占位，不能直接用于生产核算。

执行顺序拟为：确认状态检查、数据完整性检查、量纲检查、因子适用性检查、重复计量检查、公共资源分配、逐项计算、分项汇总、参考单位归一和结果封存。中间结果保留足够精度，显示舍入与核算舍入分别管理，精度与舍入规范经后续契约确认。

特别检查三个易错路径：整线电量与设备电量重复计入；自制压缩空气所耗电量与外购压缩空气因子重复计入；物料上游因子已包含某过程后又重复计入该过程。电力因子须核对其生命周期范围、温室气体覆盖和输配电处理，不能仅凭“电力”名称选用。生态环境部已发布专供产品碳足迹使用的电力碳足迹因子数据，应按适用性、年份与边界复核后登记，本稿不抄入具体数值。[官方公告](https://www.mee.gov.cn/xxgk2018/xxgk/xxgk01/202510/t20251024_1130734.html)。

公共资源分摊沿用原计划书的四类研究方向：产量、设备运行时间、贴片点数、多因素方法。它们是待比较的研究候选，不能预先认定某种方法最准确。尤其贴片点数与回流炉空载/待机能耗之间不必然存在比例关系；多因素权重也不能凭主观设置后声称适用。无实测参考时只评价方法差异、守恒和敏感性；有独立计量时再比较误差。

### 1.8 数据包、指纹与回放方案

建议采用 ZIP 文件作为交付容器，包含 JSON 权威数据、CSV 明细、可读报告和证据清单。以下为待制定规范的结构草图，并非正式发布的 DataPackage schema：

```text
package/
  manifest.json       规范版本、文件清单、校验值与回放条件
  inputs.json         已确认输入及边界声明
  rules.json          规则标识、版本及可用定义/引用
  factors.json        因子快照及许可允许的元数据/数值
  results.json        总量、分项结果与规范化数值
  quality.json        缺口、质量评价、替代假设和限制
  audit.json          候选、人工确认与必要变更记录
  details.csv         面向表格软件的明细
  report.html         人可读的结果与方法说明
  evidence/           允许交付的证据附件
```

内部完整包和对外交付包按权限区分。付费数据库、标准全文和企业证据不得因为生成数据包而自动获得再分发权。对外包无法携带全部因子值时，写明需要的数据库版本与授权条件；不得宣称任何接收者都能完全离线复算。实验回放优先使用许可允许共享的公开或合成数据。

建议采用 SHA-256 对规范化后的输入、规则、因子、算法版本和结果生成计算指纹。指纹算法和规范序列化细节须另行评审：字段顺序、列表排序、空值、Unicode、小数格式和单位都要固定；计算时间、任务流水号等运行元数据独立保存，避免同一输入因运行时刻不同而得到不同指纹。

另设包内文件校验清单，校验文件是否变动。计算指纹、包文件哈希与数字签名是不同概念；哈希不能证明资料真实、也不能单独防止有权限者同时修改数据和校验值。首期采用权限隔离、追加审计与备份支持追溯，不将其宣传为区块链或第三方认证。

### 1.9 安全、部署与运行条件

默认只监听本机地址；内网协作部署再配置认证与 HTTPS。建议设置项目管理员、数据录入者、核算复核者、只读查阅者等角色，服务端检查权限，确认、导出和权限变更均留痕。日志记录对象与操作，避免记录完整敏感 BOM 正文。

本地模型、前端资源和词典须预先下载并锁定；运行期不依赖外部 CDN 或模型下载。生产数据、备份和密钥存放于受控目录；CI 只处理合成或允许公开的数据。导入文件限制大小与类型，不执行宏，不跟随外部链接；CSV/Excel 导出对文本公式注入进行防护。

建议先在现有开发电脑上评估 CPU 模式的规则与嵌入检索，记录峰值内存和响应时间；GPU 作为本地大模型或批量实验的可选条件。配置、显存与采购预算尚无实测依据，不把某套硬件写成已经具备或必然满足要求。容器部署优先复用现有 Linux/WSL2 开发条件，同时准备数据备份、恢复和断网运行验证。

### 1.10 开发优先级

先实现不依赖 AI 的人工闭环：导入、校验、确认、确定性核算和数据包回放；随后接入规则、语义和融合检索开展比较；最后完善图表、模板映射和生成式解释。这样可以分别判断核算链路是否成立、AI 是否带来可测量收益。

首期必须完成的能力为数据字典、Excel/CSV 导入、人工确认、已复核规则与因子管理、确定性计算、缺口说明、快照与回放。实时设备接入、复杂流程编排、多租户商业化、大模型微调和全行业扩展为后续选做内容。

## 二、国内外研究现状和发展动态

### 2.1 国内研究现状

国内产品碳足迹研究正与标准、数据基础和认证实践协同推进。GB/T 24067-2024 于 2024 年 8 月 23 日发布、10 月 1 日实施，修改采用 ISO 14067:2018，为产品碳足迹量化提供通用依据。该标准不能替代具体产品的边界、数据和方法论证。[全国标准信息公共服务平台](https://std.samr.gov.cn/gb/search/gbDetailed?id=208E903AB60379F3E06397BE0A0AB2B9)。

在方法研究方面，舒印彪、赵良、易俊等在 2026 年的《产品碳足迹核算方法论体系与技术研究》中，从模型方法、数据体系、标准规范与核算认证四个方面讨论本土化体系建设，涉及分层分级建模、能源碳负荷分配和数据分级溯源。其启示是，软件计算只是链条的一部分，模型边界与数据可追溯性同样决定结果质量。本项目据此将数据字典、分摊对照和证据记录列为研究对象。[期刊摘要与题录](https://epjournal.csee.org.cn/zh/article/doi/10.13334/j.0258-8013.pcsee.260001/)。

在电子相关领域，国内已有针对线路板资源化过程的碳足迹研究。黄颖在 2026 年《不同线路板资源化技术的环境碳足迹评价》中比较不同废线路板回收工艺，并分析能源、燃料及废物处理环节。该研究说明工艺差异需要通过分项数据体现，但其对象是废弃线路板回收，不能将结论直接当作 SMT 装配阶段的排放因子或分摊依据。[期刊发布页](https://fjdl.cbpt.cnki.net/portal/journal/portal/client/paper/3c9b33089e7845c771610bca6ef44ee0)。

数据基础也在发展。生态环境部于 2026 年 6 月发布年度建设进展报告，介绍核算标准、因子数据库和制度建设进展；环境规划院于 2026 年 10 月发布的 CPCD 年度报告说明，通过企业调研和问卷整理数据瓶颈、实施成本及应用诉求。这些资料支持开展面向企业实际填报流程的数据准备研究，但不能替代本项目自己的用户调研或效果实验。[生态环境部进展](https://www.mee.gov.cn/ywdt/xwfb/202606/t20260617_1159602.shtml)、[环境规划院 CPCD 报告发布信息](https://www.caep.org.cn/ywdt/kydt/202610/t20261015_1183014.html)。

综合上述资料，本项目提出的研究切入点是：在已有标准和数据库基础上，验证一套适用于 PCBA-SMT 的工序级数据准备与交付方法。这里的“研究空间”是针对已检索样本的归纳，不应表述为国内没有相关工具、没有相关研究或已查明空白。

### 2.2 国外研究现状

国际上，ISO 14067:2018 已建立产品碳足迹量化框架，并与 ISO 14040、ISO 14044 的生命周期评价体系衔接，同时涉及部分产品碳足迹。openLCA 等软件提供生命周期建模与评价能力，ecoinvent 已包含电子领域相关数据。项目应复用其方法与可授权数据，并研究适合本地企业流程的组织方式。[ISO 官方页面](https://www.iso.org/standard/71206.html)、[openLCA 官方说明](https://www.openlca.org/faq/)、[ecoinvent 电子领域说明](https://support.ecoinvent.org/batteries-electronics)。

电子产品研究正在关注具体材料与制造路线。2024 年 Nature Sustainability 发表的《Recyclable vitrimer-based printed circuit boards for sustainable electronics》将可回收 PCB 材料与环境评价结合，说明材料和工艺选择可以成为生命周期研究的核心变量。该研究关注 PCB 基材与回收路线，不等同于企业 SMT 工序数据管理。[期刊论文](https://doi.org/10.1038/s41893-024-01333-7)。

Courtillat–Piazza 等于 2024 年公开的电子硬件生命周期研究比较了 Sphera LCA 与 ecoinvent 背景数据库，指出数据库选择可能显著影响部分环境指标。此次核对的是作者公开的 arXiv 版本；其中毒性指标的差异不能解释为所有碳足迹结果都具有同样差异。对链碳台的启示是：需要保留背景数据版本、适用对象及替代理由，而不能只保存一个最终数值。[作者公开论文](https://arxiv.org/abs/2401.17512)。

供应链数据交换方面，WBCSD PACT 已发布产品碳足迹数据模型与交换接口规范。它表明研究与产业实践正在从单个企业计算，延伸至跨系统交换和数据复用。链碳台可在完成自身规范后研究字段映射；映射部分字段不等于通过互操作性验证，更不能直接宣称获得国际认证。[PACT 技术规范](https://wbcsd.github.io/data-exchange-protocol/)。

### 2.3 发展动态与本项目定位

结合上述来源，可以归纳出四个与本项目直接相关的发展方向：

| 方向 | 对项目的具体要求 |
| --- | --- |
| 通用规则向行业数据和本土背景数据落实 | 工序、计量对象、时间与地域必须显式表达 |
| 单次计算向供应链数据复用发展 | 导出结构化数据与来源，保留版本和客户模板映射 |
| 结果披露向过程核验延伸 | 保留原始数据位置、人工确认、因子快照和回放条件 |
| 智能检索进入数据准备流程 | 通过可重复实验验证收益，同时保留人工审核和拒答 |

本项目的重点不是提出新的碳足迹基本核算理论，而是围绕 PCBA-SMT 场景研究“字段规范化—候选匹配—分摊适用性—结果回放”的协同方法。国内外研究已提供理论和工具基础，项目贡献应通过可公开的数据结构与对照实验具体说明。

## 三、创新点与项目特色

### 3.1 面向工序活动的数据字典及关联表达

围绕物料、工序、设备、活动数据和证据组织统一字段，不仅定义字段名称，还定义量纲、期间、计量对象、来源、可空性和确认状态。创新重点在于对 PCBA-SMT 具体场景形成可复用表达，并验证不同来源表格转换后的信息保留情况。成果以字典、模板、映射规则和缺口案例共同体现。

### 3.2 语义与业务约束结合的候选匹配方法

将规则词典与语义召回结合，把单位、工艺适用性和因子边界作为约束；对缩写、中英文混排、描述缺失与歧义分别评价。通过规则、语义、融合三组及消融对照识别各环节贡献，并引入拒答状态。创新点是受约束的场景方法与评测，不是“使用了大模型”本身。

### 3.3 面向公共资源的分摊适用性研究

针对共享设备及公用工程，比较产量、时间、贴片点数和多因素方法在不同生产情景中的差异，区分直接计量、具备合理分配依据和信息不足等情况。研究目标是给出适用条件、风险和敏感性，不预先追求“某一算法普遍最优”。

### 3.4 可回放碳数据包与过程证据设计

将结果与输入、因子、规则、版本、缺口和人工确认组织成一个可校验交付单元；通过导出后重新导入、修改输入和证据缺失等实验验证其复核能力。创新重点在于“能否复算、缺什么才能复算”的明确表达，而不是只生成一份报告。

### 3.5 项目特色

项目以中小企业已有表格为起点，支持本地处理和人工可控流程，适合学生团队以原型开展研究。AI 不承担正式算数，核算引擎独立运行，便于分析错误来自数据、映射、规则还是因子。即使 AI 未显著提高效率，字典、确定性链路、数据包与实验结论仍可形成有效成果。上述内容应定位为场景方法与工程集成创新，暂不使用“国内首创”“国际领先”等缺少系统检索证据的表述。

## 四、技术路线、拟解决的问题及预期成果

### 4.1 技术路线

研究按“标准与需求核对—工序数据模型—数据集与基准—规则/语义/融合匹配—确定性核算与分摊对照—数据包与回放—四组实验—结论与成果固化”推进。

第一步明确场景、数据边界和评价对象；第二步形成字典与契约，建立标注手册；第三步先实现人工闭环与规则基线，再接入语义算法；第四步开展资源分摊与数据包实验；第五步对差异、误差、失败案例和局限性作出解释。每个阶段都形成可核验产物，而不是只以“模块开发完成”作为研究进展。

### 4.2 拟解决的关键问题

| 关键问题 | 研究或技术方法 | 阶段结果与验证 |
| --- | --- | --- |
| BOM 字段及描述不统一 | 表头映射、词典、文本归一、语义候选与人工复核 | 字段映射结果；按样本类别统计正确与修正情况 |
| BOM 与实际工序关系不明确 | 结合工艺路线、设备记录和人工确认建立多对多关系 | 经复核的物料—工序映射；保留不确定关系 |
| 活动数据缺失或重复 | 明确期间、计量对象、来源等级与资源流标识 | 缺口清单、重复计入检查和阻断案例 |
| 因子名称相似但边界不同 | 来源/单位/区域/版本复核，补充技术与边界适用性检查 | 因子候选、拒答与人工确认记录 |
| 公共能耗分摊依赖假设 | 四类方法比较、守恒检查和情景敏感性分析 | 方法差异及适用条件，避免无实测依据的准确性判断 |
| 结果和依据难以复核 | 冻结快照、明确数值规则、数据包校验与独立回放 | 回放记录、错误检测结果和复算所需条件 |

### 4.3 数据集建设与防止评价偏差

沿用原计划书“不少于 1000 条可标注样本并保留独立测试集”的建设目标，来源为许可允许的公开资料、独立重建的脱敏结构、人工扰动与合成样本。样本集是计划成果，目前不能写成已经建成。

明确一条样本的任务类型、来源、输入、候选集合和人工参考答案；一条 BOM 行不能自动等同于一条完整核算案例。匹配数据集、完整计算案例和用户操作记录分开管理，分别报告数量与覆盖。

按原始来源、产品族或同源模板分组划分开发集和测试集，同一原始记录的缩写变体、顺序扰动及合成派生不能跨组泄漏。记录原始样本数与派生样本数，避免把大量近重复样本解释为行业覆盖。标注采用交叉复核，分歧由领域复核人裁定；无法确定适用因子的样本允许以“无可用候选”作为正确状态。

### 4.4 四组对照实验

| 实验 | 对照和变量 | 指标与判定 | 必须说明的局限 |
| --- | --- | --- | --- |
| A：候选匹配 | 规则、语义、融合；必要时去除单位/边界约束做消融 | Top-1、Top-3、人工修正率、拒答覆盖、错误接受率、单条处理时间；给出分类型结果与不确定性 | 测试集不用于调参；模型分数不是概率；合成样本不能代表全部企业数据 |
| B：公共资源分摊 | 在各方法适用条件下比较产量、时间、点数、多因素；考察待机、换线、小批量等情景 | 分配守恒、结果差异、参数敏感性；有独立实测参考时再报告误差 | 守恒不等于正确；方法差异不等于真实误差；禁止以想要的结论调整权重 |
| C：流程效率 | 相同任务用 Excel 与工具完成；交叉安排工具顺序，统一培训 | 完成时间、操作步骤、确认后错误率、未完成任务数；报告人数和任务难度 | 避免把熟悉程度和练习收益计入工具效果；不得预写提升百分比 |
| D：可审计与复算 | 固定快照重复执行、导出后回放、改变规则/因子/输入、缺失或篡改附件 | 规定环境内精确结果与计算指纹一致；应变动的指纹变动；缺失/篡改能被检测；必需字段齐备 | 全包字节可能因打包时间变化；哈希不能证明来源真实；授权不全可能限制外部回放 |

实验 A 中命中率的样本分母、人工修正率的计算范围和拒答处理在实验前冻结；可多解任务采用复核过的可接受答案集合。实验 C 纳入审核和纠错时间，不只统计模型推理时间。实验 D 中“字段齐备”也不等于资料真实或符合全部标准要求。

建议将规定环境下复算结果与指纹完全一致、必需字段校验无遗漏设为硬性工程验收条件；这些是拟定要求，并非已取得的 100% 实验成绩。AI 命中率和效率目标经基线测量后确定。样本量、人员数量与统计方法由实验负责人及指导教师在开测前确认。

### 4.5 本部分预期形成的研究结果

形成工序数据表达方法、受约束匹配方法及失败模式分析、公共资源分摊适用性比较、数据包回放验证四类研究结论；实现一个承载这些实验的工具原型。此处强调研究回答了什么，第八部分列明最终提交的文件与成果数量。

## 六、与本项目有关的研究积累和已取得的成绩

### 6.1 可由现有材料支持的研究积累

项目已形成计划书与答辩材料，明确了面向 PCBA-SMT 中小供应商的数据准备场景，将研究内容划分为工序数据字典、BOM 候选匹配、公共资源分摊、确定性核算及可审计数据包。已经建立项目目录和文档管理结构，形成模块职责、核心实体清单、数据安全规则及协作流程。

### 6.3 当前成绩的表述边界

截至本次核对，能确认的是“研究方案与工程组织基础已建立”。尚未发现可运行的业务原型、已复核的正式因子数据、已完成的千条标注集、四组实验结果或软著/论文成果凭证。因此不应写“已经实现高准确率”“已经降低企业成本”“已获得认证或知识产权”。可将本节定位为前期研究积累与阶段性文档成果。

建议申报表正文使用：

> 项目组已完成研究问题与应用场景梳理，形成项目计划书、功能流程、模块职责及初步评价体系；建立了工序、单位、公式和因子来源的登记框架，以及数据安全和版本追溯约束，并明确采用“AI 候选—人工确认—确定性计算”的方法。现阶段已具备开展数据集建设、原型开发和对照实验的设计基础，后续将重点完成标准条文复核、样本标注、算法实现与实验验证。
