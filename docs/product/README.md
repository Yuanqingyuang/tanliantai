## 二、产品定位

**一句话**：AI 辅助的 PCBA-SMT 工序级碳数据字典、核算工具与数据包。

**为谁做**：

| 客户类型 | 特征 | 他们要什么 |
| --- | --- | --- |
| 核心客户 | 以 PCBA / SMT 为主的中小电子制造企业与电子制造服务商：50—500 人、1—5 条贴片线、无专职碳管理岗 | 客户索要碳数据时，能用最低成本把自己的数据变成可交付的核算结果 |
| 次核心客户 | 整机品牌与链主企业的供应链碳管理岗 | 向数十到数百家供应商收集口径统一、可比可核的数据 |
| 生态客户 | 碳足迹核算与绿色供应链咨询机构、第三方检测认证机构、地方园区与行业协会 | 批量处理并复用标准数据包 |

**我们做什么**：把企业已有的数据（BOM、工序、设备、活动记录）变成可交付的产品碳数据。
**我们不做什么**：不做通用 LCA 建模软件，不做整机与组织层面的能碳管理平台，不替企业出具第三方认证结论。

## 三、价值主张

| 现状 | 链碳台的差异 |
| --- | --- |
| 通用 LCA 软件：需专业人员与完整活动数据，缺工序级字段口径与 BOM→工序映射 | 面向中小供应商的低门槛数据准备，内置工序级数据结构与字段映射 |
| 咨询与核算服务：约 2 万元/产品，按次付费，数据难沉淀 | 数据一次准备、多年更新、多模板复用，形成可复用资产 |
| 能碳管理平台：约 10 万元/套，面向大型企业的整机与组织口径 | 轻量、聚焦产品碳足迹与工序级数据，支持本地部署 |

## 四、MVP 范围（第一期）

**目标**：跑通"一个 PCBA 产品、一条工序链、一份可复核数据包"的完整链路。

| 范围内（Must） | 说明 |
| --- | --- |
| 数据字典 V0.1 | `Product` / `BOMItem` / `Process` / `ActivityData` / `EmissionFactor` 的字段与单位口径 |
| BOM 与工序导入 | 支持模板导入与字段映射，AI 只给候选、人工确认 |
| 活动数据录入与质量等级 | 期间、来源、单位、缺口标记 |
| 确定性核算 | 依据登记公式与因子计算，同一输入 → 同一结果 |
| 数据包导出 | 含结果、证据、因子来源与版本、缺口、修改记录、计算指纹 |
| 审计链 | 输入快照、规则版本、结果指纹可回放 |

| 范围外（Not now） | 原因 |
| --- | --- |
| 第三方认证对接、EPD 正式申报 | 需要资质与商务前提，非首期 |
| 组织级碳盘查与范围三全量核算 | 口径与产品碳足迹不同，避免与定位混淆 |
| 多产品线大规模并行与性能优化 | 先证明方法与链路正确，再谈规模 |
| 全自动 AI 核算 | 与"AI 不下场算数"的架构原则冲突 |

## 五、用户流程（核心场景）

```text
① 建项目与产品
   └─ 定义产品、功能单位、系统边界（核算对象）
② 导入 BOM
   └─ 模板导入 → 字段映射（AI 候选 + 人工确认）→ 物料口径统一
③ 建立工序链
   └─ PCBA-SMT 工序与设备 → 工序级活动数据需求清单
④ 录入/导入活动数据
   └─ 电量、工时、辅材、产量等 → 校验 → 质量等级与缺口标记
⑤ 因子匹配
   └─ AI 给候选 → 来源/单位/区域/版本四重校验 → 人工确认 → 因子快照
⑥ 运行核算
   └─ 规则约束 → 确定性计算 → 结果与指纹（可复算）
⑦ 分析与复核
   └─ 总量与分项构成、工序/物料贡献、方案与敏感性对比
⑧ 导出数据包
   └─ 结构化交付物，供客户模板映射与复核
```

每条流程的输入输出与界面归属见 [应用外壳](../../app/shell/README.md) 与各 [业务模块](../../modules/project/README.md)。
