# 任务分解（WBS）

> 状态：草案
> 说明：本文件按**交付物**切分任务，负责人原则上留「待认领」，确认人留「待确认」；人员商定后再回填 [任务台账](tasks.md)。T-0001、T-0002 已由赵天志执行，是当前已确定负责人的例外。

## 一、使用规则

- 每个任务在 [任务台账](tasks.md) 中有唯一 `T-xxxx` 编号，除 T-0001 外本表与台账一一对应；T-0001 是 WBS 建立前的治理任务，只在台账保留。
- 切分粒度按 3–5 天可完成判断；超过 5 天的任务继续拆，不靠加人解决。
- 任务标题必须可判定完成，验收标准写"看什么、谁签"，不写"做好即可"。
- 影响目录用于并行分区：同一文件同一时间只有一个负责人（见 [collaboration.md §3](../../.agents/policies/collaboration.md)）。
- 核算口径类任务，负责人与确认人不得为同一人（见 [任务台账](tasks.md)）。
- 负责人、确认人未定时不阻塞切分；未开工任务状态保持「待认领」，已交付待复核的任务按台账转「待评审」，不得跳成「已完成」。

## 三、关键路径

```text
T-0002 技术基线
  → T-0010 技术验证
    → T-0011 数据字典 → T-0012 契约 → T-0022 核算引擎
      → T-0026 数据包/回放 → T-0028 四组实验 → T-0029 评测报告
        → T-0031 规范冻结 → T-0035 结题材料
```

可并行启动的分支：

- T-0003、T-0005、T-0006 可在技术验证之前并行；
- T-0016–T-0018 数据集建设在 T-0009 许可清单完成后即可开始，不等系统开发；
- T-0015 导入模板依赖数据字典，但可以先做字段草案；
- T-0036 认证权限依赖契约，可与 T-0019 最小集成并行；
- T-0027 结果分析可在核算引擎稳定后与数据包任务并行。

## 四、阶段关口

| 阶段 | 关口条件 |
| --- | --- |
| 一 | ADR 0003 签注；案例产品与边界确定；四组实验指标冻结；技术验证给出结论 |
| 二 | 数据字典、契约、数据包规范 V0.1 评审通过；认证与权限矩阵通过；样本分期达到 300/600/1000；最小集成可启动 |
| 三 | 人工闭环可用；核算引擎复算一致；AI 关闭不影响核心核算 |
| 四 | 四组实验有完整结论；案例包可回放；系统测试报告完成 |
| 五 | 字典/规范 V1.0 冻结；软著与结题材料齐备 |

## 五、本期不做

微服务集群、区块链、在线交易平台、全厂物联网、实时设备接入、多租户商业化、大模型微调、全行业扩展。以上内容即使出现在答辩材料中，也不进入本期任务台账。

## 六、与人员分配的关系

本表原则上只切分任务，不分配人员；T-0001、T-0002 已由赵天志执行，是当前例外。其余任务在人员商定后：

1. 在 [任务台账](tasks.md) 中把「待认领」改为具体负责人；
2. 同时填写确认人，核算口径类任务确认人不得与负责人相同；
3. 按影响目录检查并行冲突，同一文件同一时间只保留一个负责人；
4. 若单人任务超过 5 天，继续拆任务，不靠加班消化。
