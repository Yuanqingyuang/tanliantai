## 零、免责声明与使用说明

> 这一节比后面的内容重要，请先读完再往下看。

**1. 这是建议稿，不是派工单。**
本文件由 AI 起草，用来把"要做哪些事、怎么算做完"讲清楚，供团队讨论。角色、周次、交付日、交接对象都是建议，不是决定；商定后以任务台账为准。**本文件的角色分工（R1–R5）与 WBS 依赖已对齐；若再调整，先改 `wbs.md` 与台账，再回改此处。**

**2. "行动参考"不是操作指令。**
"第 N 周行动参考"里的每一条，是讨论时想到的一种做法，不是唯一做法，更不是必须照做。增、删、换顺序、换方法都可以。它存在的意义是：没有头绪时给个起点，不是替人思考。

**3. 判断权在执行人。**
任务书按"读者可能没做过"来写，所以细。如果执行人比它更懂，按自己的判断来，不必迁就文档。有更好的路径，直接改文档并在群里说一声——这份文件本来就该被改。

**4. 验收标准是底线，不是方法。**
验收自检、判定口径、红线这几处是硬的，因为它们决定"算不算完成"。达到标准就算合格，用什么路径达到，由执行人决定。

**5. 偏离要留痕。**
和文档写法不一致的地方，在交付报告的"变更摘要"或"验证"里写一句为什么。这不是请罪，是让别人能接上手。

**6. 文档会错。**
标准条款、链接、数字、流程都可能过时或有误。发现错误直接改，PR 里说明。以标准原文、学校要求和实际情况为准，不以这份文档为准。**例外：验收标准只能由确认人修改，执行人可以提建议，但不能自行下调。**

**7. 责任边界。**
本文件只负责把选项、依赖和验收条件摆出来；采不采纳、怎么执行、最后谁签注，由执行与确认环节决定。

## 七、协作规则

### 7.1 确认人

负责人不能确认自己的任务。资料类抽查，口径类逐条看。

**确认人须先答应**：本表是拟安排，发布前要逐位征得同意；未同意的任务视为「待确认」，不得在群里宣布已定。确认人临时无法履职时，由项目负责人改派并更新本表。

| 任务 | 确认人 | 怎么确认 |
| --- | --- | --- |
| T-0003 / T-0009 / T-0005 / T-0006 | 袁青扬（项目负责人） | 抽查 3–5 条 |
| T-0004 / T-0007 | 技术负责人 | 逐条对照验收表 |
| T-0008 | 指导教师 | 口径签注；技术负责人只出技术复核意见，不占确认人 |
| T-0010 | 袁青扬 | 跑一遍 README |

**避免单点**：技术负责人同时承担 R5 执行与 T-0004/T-0007 两项确认，**T-0007 于 11.24 冻结，确认须在 11.27 前完成，最迟 11.30**；台账登记改由 R3 承担，关口评审由两人共同主持。

### 7.2 交付流程

1. 群里报"角色 + 姓名"认领；台账登记由 R3 承担（5.5 人日里留了 0.5 天杂项，正好覆盖），状态转「进行中」。
2. 建分支（`docs/t-0003-standards`），PR 标题带 `[T-0003]`，不直接推 main。
3. 交任务说明 + 交付报告（`.agents/templates/`），验收标准逐条对照。
4. CI 四项（structure / data-safety / links / change-guard）全绿才能合。
5. 确认人签注「通过 / 有条件通过 / 退回」+ 日期，落在台账「确认」列与交付报告 §10，缺一不算完成。

### 7.3 每周节奏

- 周一：建议开 15 分钟站会（主持人组内轮值），逐人过台账状态，无进展说明原因；纪要由主持人指定一人记录
- 周三：卡点上报（约不到企业、找不到标准文本、环境装不上）
- 周五：当周应交付的任务开 PR

### 7.4 交接包

每个角色维护一页交接包，只写五项：当前进度、未完成项、文件位置、卡在哪、下一步。周更一次。换人或请假时，接收人照这一页即可接手，不需要口述。

- 路径：`docs/planning/tasks/<编号>/handoff.md`
- T-0005 的两个交付段写在同一页里，按 a/b 分两小节
- 其余任务一个编号一页

### 7.5 判定口径

| 项 | 定义 |
| --- | --- |
| 来源等级 | 沿用 `knowledge/README.md` 已有的 L1–L5：L1 标准、L2 政策与官方文件、L3 学术文献与数据库方法学、L4 行业数据、L5 企业实测；L4 仅作背景与合理性检查，不单独支撑核算结论 |
| 可比研究 | 同时满足功能单位可换算、边界范围一致、数据年份相差 ≤3 年、地域一致；缺一项只能写"仅作量级参考" |
| 冻结 | Git tag + commit hash，文档内写版本号与日期，三者缺一不算冻结 |
| 退回 | 确认人给「退回」须写明缺哪条验收；负责人 5 个工作日内补交或申请改标准 |
| 基准机 | 团队共用的一台机器，T-0010 的阈值只认它的结果；其他机器数据仅作备注 |

### 7.6 争议与升级

验收结论有分歧时，先由确认人书面说明依据；仍不一致的，交项目负责人裁定并记进交付报告；涉及核算口径的，由指导教师裁定。裁定过程要留痕，不许口头了事。

### 7.7 红线

- 企业真实 BOM、工艺参数、能耗、价格、客户信息一律不入库，访谈记录必须脱敏。
- **本仓库是公开仓库**（`Yuanqingyuang/tanliantai`，已核实为 PUBLIC）：访谈原始记录、录音、含企业信息的纪要一律不入库；入库的只有脱敏痛点清单与结论。
- `docs/` **不在** `check_data_safety.py` 的扫描范围内（它只扫凭据、文件名和 `data/`、`tests/fixtures/` 的内容），放进去的东西 CI 不会拦，只能靠人工把关。
- 访谈录音只存本地加密目录，不进仓库、不进网盘，90 天内删除。
- 云端 AI 只处理公开/合成/脱敏数据，真实数据走本地。
- 每条工艺事实、每个系数必须有可核来源，AI 只做候选。
